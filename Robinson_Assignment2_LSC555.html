Using Nielsen’s Heuristics in the Perspective of Undergraduate Instructors

  • Visibility of System Status: loading circle pops up when using searching but it is not showing real progress, just spinning.
  • Match between system and the real world: the term “serials” is used to describe the type of content. I think the terms "publications" or "magazines" would be more real world friendly, especially for undergraduate students who aren't familiar with primary-source database research.
  • User control and freedom: There are instructions that show how you got to a specific publication and at the top of the page there are hyperlinks to various parts of the process to go back, there is also a “Back to results” option, the browser back arrows also work
  • Consistency and standards: There are few symbols, but those that are used are familiar for the majority of people and locations of items are consistent across items.
  • Error prevention: There are two search bars, one that searches within The Tower and one that searches all of JSTOR, which is slightly confusing.
  • Recognition rather than recall: The download, save, and search symbols used are all familiar to anyone new to the website.
  • Flexibility and efficiency of use: the only way to shorten the number of issues is to search a term or mess with the date range. For example, when you search a term/phrase, like "Black History", the results given are 96, instead of 2,262.
  • Aesthetic and minimalist design: Colors are white, red, and black and the detailed information is kept behind drop down arrows, adding to the minimalist design, which helps undergraduate students and instructors who may be distracted by an abundance of information.
  • Help users recognize, diagnose, and recover from errors: If you misspell a search, no results are found, but there is a “Did you mean:” section, that gives an alternative search.
  • Help and documentation: There is a “Search help” hyperlink that gives tips on how to find information, there is a question symbol in the top right corner with “get support”, “help logging in”, and “contact us". This could be helpful for undergraduate students who are unfamiliar with research or instructors who are not getting the results they are looking for.

Site Analysis Summary

When opening an issue, the site returns detailed data, including the title, collection, date, page count, language, related issues, and copyright information. Searching for a term within an individual issue results in the word being highlighted whenever used within the pages. Searching for terms within the entire Tower archive, produces the number of results including those terms, with short descriptions showing where the term appears in the issues. Finally, sorting by newest reorganizes the items from newest to oldest. Overall, these inputs showcase how the system is able to search within the documents, organize results, and provide descriptive metadata for the digitized newspaper content, making it significantly easier for the user to navigate through the thousands of issues.

The site performs exceptionally well in “User control and Freedom” and “Aesthetic and Minimalist Design”. With user control and freedom, users are able to see how they got to the issue where they are and how to get back to different points in the search process. The “Back to Results” also brings the user back to the results page when a term or date is given, or the list of all issues if no search terms were given. Also, the user is able to utilize the browser’s back arrows, which makes navigation familiar for the user. For “Aesthetic and Minimalist Design”, the website utilizes a consistent color scheme and large amounts of information are kept behind a drop down arrow, so the user isn’t bombarded with information once the webpage loads.

Two weaknesses for the site include: “Visibility of System Status” and “Error Prevention”. For “Visibility of System Status”, the user is unable to get a quantifiable output for the time it would take for the website to produce results, nor does it give a proper indication of where the user is in the waiting process. For “Error Prevention”, the site has two search bars, one that is for the entirety of the JSTOR website, while the other searches just The Tower archive. This makes it easy for the user to accidentally search in the wrong bar, which would produce results that would not be desired by the user. Overall, The Tower archive provides the user with easy access to the sources, but updates to system feedback and search features could make it more streamlined for undergraduate instructors using the website for research and planning.

Mini Usability Test

Part 1 & 2 Comparison

My heuristic analysis and the observations of the user for the “mini-usability test”, have a lot in common. Both tests find the aesthetic appealing and the symbols used are intuitive. While my heuristic analysis focused more on the website’s navigation within JSTOR, the user I observed usually utilized the browser’s back buttons. However, once the user began using JSTOR’s in site navigation, he noted that it was much faster at returning to The Tower’s landing page. Both experiences note that the highlighting of the search within the issue feature is helpful for locating terms within the newspaper page. Both I and the user I observed, noted issues with the loading process and how it does not give accurate wait times, but instead a continuously spinning loading indicator.

In my analysis, I found the two search bar features very confusing, however the user I observed noted that issue, but found more frustration in the search feature not finding the information he was actually looking for. While during my analysis, I was able to find the information I was looking for using the search feature, the user I observed did not. I think that highlights the difficulty in usability of the search feature. The user searched for much broader information that I was, and results were returned that included any term in the phrase, while I searched my terms in quotation marks. When searching for information relating to World War II, the user searched “World War 2” and no results were given, and while that was user error, the site does nothing to correct it.

Suggestions for Improvement

Overall, I find The Tower's JSTOR website better than many other research databases I have used. However, there are still areas for improvement.

  1. Remove the double search bar: I would suggest moving the search bar for all of JSTOR behind a drop down.
  2. The loading circle doesn’t show real progress:I suggest a progress bar or an estimated wait time.
  3. Searches don’t have error prevention: Users should be able to see why their searches are possibly not returning results. For example, when searching “World War 2”, related searches of “World War II" and “WWII” should be recommended.
  4. Removal of the term “Serials”: Replace archival terminology with common language, such as “Newspapers”.
